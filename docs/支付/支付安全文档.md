# 🔥 支付安全，必须特别注意的关键点



| 领域             | 具体安全问题                                                 | 防护办法                                                     |
| ---------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **回调安全**     | - 回调伪造（别人假冒微信推送） - 重放攻击（截取回调再发一次） | - 签名验证（强制验证每个回调签名） - 订单状态幂等处理（支付一次只处理一次） |
| **金额安全**     | - 支付金额被篡改                                             | - 后端以自己的订单金额为准，不信任客户端传来的金额           |
| **订单校验**     | - 支付后找不到订单 / 支付结果异常                            | - 后端查询数据库验证订单是否存在、金额一致                   |
| **前端安全**     | - 用户伪造支付成功前端页面（骗服务器发货）                   | - 后端回调为主，前端支付结果只是提示，不能作为唯一依据       |
| **接口暴露**     | - 回调API地址被乱调 / 扫描                                   | - 校验来源IP（可选） - 校验接口内部逻辑，比如订单校验、签名  |
| **数据传输**     | - 抓包篡改                                                   | - 全部走HTTPS                                                |
| **日志安全**     | - 日志泄漏敏感信息（比如订单号、用户ID、签名）               | - 日志敏感信息打码或者不记录                                 |
| **退款风险**     | - 恶意退款、假冒退款                                         | - 退款前二次验证：金额、用户身份校验                         |
| **重复支付**     | - 网络延迟导致重复支付                                       | - 后端对同一订单号，只允许更新一次状态，重复的忽略           |
| **支付成功状态** | - 微信异步回调慢，用户误以为没支付                           | - 前端提示：“请耐心等待支付确认”，后台实时同步订单状态       |





# 🚨 下面几个特别常见的坑要注意

1. **签名校验一定不能省**
   - 任何支付回调、支付同步通知都必须校验签名。
   - 不然别人可以伪造成功支付！
2. **回调接口一定做幂等**
   - 微信可能推送好几次同一个订单支付成功，如果你不做幂等，可能发货发好多次。
   - 幂等处理=已经支付过的订单不再重复处理。
3. **金额核对必须做**
   - 微信推过来的金额和你本地订单金额要比对。
   - 小心别人支付1分钱，骗你发高价商品。
4. **服务器宕机要能重试**
   - 如果服务器宕机、处理失败，不怕，微信会继续推送通知。
   - 所以要保证回调接口稳定，能正确处理重发。
5. **退款也要做好安全校验**
   - 退款接口要二次确认：比如校验用户身份，或者后台人工审核。





### 微信支付的回调

- # 🌟 回调的作用？

  在你的服务器，用来：

  

  | 作用         | 举例                            |
  | ------------ | ------------------------------- |
  | 修改订单状态 | 把订单从 "未支付" 改成 "已支付" |
  | 发放奖励     | 给玩家发金币、道具              |
  | 推送消息     | 通知用户“支付成功”              |
  | 触发后续流程 | 比如开通会员、发货              |







- # 🛡️ 正确流程应该是：

  **支付平台（比如微信/支付宝） -> 发送回调通知 -> 你的服务器：**

  1. ✅ 验签：**确认消息是真的**，不是伪造的。
     1. 回调是“网络通知”，黑客可以自己伪造一条 POST 请求来告诉你“我支付成功了”，实际上他根本没付钱。
     2. 如果不严格校验签名，任何人都可以冒充支付平台。
  2. ✅ 查数据库订单：**确认订单存在**。
     1. 防止多次发货/多次发奖励
     2. 如果你每次回调都插一条"支付记录"，就可能出现：
        - 用户付一次钱
        - 系统记了两次支付记录
        - 给了用户两倍的金币/物品！
  3. ✅ 校验订单状态：如果已经支付过了，**直接返回 success**（防止重复处理）。
  4. ✅ 校验金额一致：**不能只根据回调信任金额**，一定要用数据库里的金额对比。
     1. 如果你只信任回调里面传的订单号、金额，没有去核对自己数据库，就可能出问题。
  5. ✅ 更新订单状态为已支付（只有一次！）。
     1. 支付平台（微信/支付宝）为了保证通知成功，会反复推送同一个回调（比如断网、超时等情况），你必须让更新订单是**幂等**的。
  6. ✅ 返回 success 给支付平台。
     1. 防止支付平台继续重试推送
